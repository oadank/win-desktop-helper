# 本服务自身行为坑（跨应用通用，与具体软件无关）

## wait_for 必须带窗口定位；不带定位扫全桌面必然超时

_记录日期: 2026-09-19 · 状态: **已修复并实测上线**（build 09-19 03:59, commit `c88818b`）_

**踩到的坑**：`/wait_for` 只传 `text` 不传 `hwnd`/`title` 时 `pid=0`，会遍历桌面上**全部**顶层窗口，撞上 Electron 大 DOM 必然 7 秒超时，还白记一个泄漏线程（`leaked_total` 当场从 0 变 1）。

**给调用方**：`wait_for` 必须带 `hwnd=`（`list_apps` 现取）或 `title=`。不带定位现在 **14 毫秒**就被拒（旧版 7 秒超时 + 白烧线程）。“等任意窗口出现某文字”不支持，也不该支持。

**修复内容**：扫描跳过 UIA 禁用应用的窗口（否则 `wait_for` 会绕开入口拦截白烧 8 秒）+ 每窗口限量 250 元素、单窗耗时上限 1200ms，成本有界；`WaitFor` 入口强制定位，并区分“没传定位”和“传了但句柄已失效”两种提示。

**实测数据（全部通过，别只看一条就下结论）**：
- 正向真命中：资源管理器 `text=回收站` → `satisfied:true` `matched:"回收站"`，**84ms / 1 次采样**（服务端精确名过滤走快路径）。
- 反面对照：同窗口等一个真没有的词 → `satisfied:false` 1625ms / **4 次采样**，证明是真在轮询而非扫一次就定论。
- `disappear=1`：不存在即达成，226ms / 1 次。
- 测完 `/health` 的 `uia.leakedTotal` 仍是 0，没再白烧线程。

**方法论教训（值得所有 agent 记）**：`disappear=1` 返回“达成”**不能**当作“扫描读得到内容”的证据 —— 完全读不到时它同样通过。验证探测类能力必须**正负两条各测一次**，我这次差点就被自己的成功案例骗过去。

**同轮已生效的收益**：`expect` 从“睡 900ms 扫一次”改成轮询；配合 `window_state`（零副作用查状态）和按进程隔离的熔断，WorkBuddy 这类必挂应用从“白等 8 秒 + 全服务连坐只能重启”变成 **13 毫秒**拦下并给出替代路子。

## P0-3 资源台账验收踩到的 5 个坑 + 一条不可越界纪律（2026-09-19 实测）

_记录日期: 2026-09-19 · 应用: self_

**1. PowerShell 函数名绝对别用单字母 `H`／`G`。** `h` 是内置别名 `Get-History`，定义 `function H($u)` 后调用 `H '/diag/resources'` 会被解析成"把路径当 `-Id` 传给历史命令"，报 `无法绑定参数 Id` —— 而错误只出现在 stderr，主输出看起来像"返回空值"，差点被我当成"服务没登记"。**函数名一律起有语义的名字**（`Fetch`/`CallApi`）。

**2. 单引号字符串里 `\"` 不是转义。** 我为了把 Windows 路径塞进 JSON-RPC 请求，手写成 `'{\"path\":\"C:\\...'` → 整条 JSON 是废的，`pin_image` **根本没发出去**，账本当然是 0。拼 JSON 一律用 `@{path=$png;x=260} | ConvertTo-Json -Compress`，别自己转义。
> 关键教训：那次"回收没生效"的结论是**假的** —— 真实原因是我压根没执行动作。**报告失败前先确认动作真的发生了**（桥有没有回 `ok:true`、rect 对不对）。

**3. 手拼 JSON 的闭合括号错位，会让字段掉到上一层，读的人看到"假空值"。** `ResourceLedgerJson` 里 `j` 已经自带 `}`，我又把 `pinLedger` 直接拼在尾巴上 → 它跑到了 `detail` 外面，按 `.detail.pinLedger` 读就是空数组。已改成 `j.Substring(0, j.Length-1) + ... + "}"`。**查这类问题先打印原始返回**，别只信解析后的对象。

**4. win 系列端点是路径式 verb**：`/win/close?hwnd=` 对，`/win/manage?verb=close` 错（404）。手册里明写着，我又踩一遍。

**5. 🔴 不可越界：别拿"本服务自己的无名可见窗"当测试目标去关。** 验收贴图销账时，我从 `listall` 里挑了个 `visible=true` 且 title 为空的窗关掉 —— 那**未必是贴图**（服务常驻就有无名辅助窗：划词球、.NET 消息窗、GDI+ 窗）。事后复查：任务栏音量 `calls=4331` 正常、划词 `enabled=1` 正常、服务没重启，**这次没弄坏东西，但属于运气**。正确做法：贴图窗必须由账本给出确切 hwnd，只关账本里登记过的那个。

**验收结论（已实测）**：贴图入账 `pinnedWindows=1` → 明细 `pinLedger=[{"hwnd":2294070,"ageSec":4}]` → 用该句柄 `/win/close` 返回 `closed:true` → 销账 `pinnedWindows=0 / pinClosedTotal=1`，桌面残留 0。回收器 `gcTicks` 随时间递增（首轮 20s 后触发，故刚重启时读到 0 属正常，别误判成没启动）。

**顺带一条判断依据**：截图目录 30 分钟内从 508 涨到 510 个文件，新增的是 `qr_huge.png` —— **不是本服务写的**。这正好证明"按目录扫射删旧文件"有多危险：这个目录里同时有用户的截图、别的 agent 的中间图，谁都不该被自动清理。回收只能针对**自己登记过的**文件。
